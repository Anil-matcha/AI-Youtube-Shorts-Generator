# v2.1 development preview

The v2.1.0 release includes these opt-in development-preview capabilities.
Manual scheduling requires explicit approval and public-publication acknowledgement;
representative OCR footage and connected-account provider behavior remain
verification follow-ups, not guarantees of this release.

## Local story evidence

Open a completed local project and use **Local story evidence** in Export.
Select on-screen OCR, speech activity, or both. Choose the source start and
duration, then Analyze. Nothing runs merely from selecting a model or opening
a project. Results are available in the Performance panel's Story search.

The fixed budget is 120 seconds, eight sampled OCR frames, one concurrent
analysis, and a 90-second operation deadline. FFmpeg frame dimensions are
bounded, audio is mono 16 kHz, and the shared media budget also applies.
Cancel stops an in-flight analysis; Clear removes saved evidence. Failed or
cancelled analysis preserves the previous complete result. Each successful
analysis replaces the previous evidence window for that project.

Tesseract must already be installed locally with the selected language data
(for example `eng` or `eng+fra`). Set `LOCAL_TESSERACT_PATH` to its executable
if it is not on PATH. The adapter uses the official
[Tesseract TSV output contract](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html).
It retains confidence-filtered text lines and timestamps, not frame images.

Speech activity uses the Silero ONNX model already bundled with
[faster-whisper](https://github.com/SYSTRAN/faster-whisper/blob/master/faster_whisper/vad.py)
and its local ONNX runtime. It detects speech regions, not laughter, music,
emotion, or speakers. No dependency, model, or media download occurs during
analysis. Only contained local source media is accepted by default; the
existing administrator-controlled external-path setting still applies.
Evidence text redacts URL/path patterns and known credentials. Review OCR
accuracy and sensitive on-screen text before sharing project backups.

API: `GET /api/v1/story/models` and
`GET/POST/DELETE /api/v1/jobs/{job_id}/story/analyze`. POST requires an explicit `ocr_model`
and/or `audio_model`; the model identifiers are `tesseract` and `silero-vad`.

## Manual YouTube provider scheduling

Create a private review intent with the existing Export controls, then refresh
the provider schedule panel. Approval records a fingerprint of the chosen
clip bytes, metadata, and generated publishing assets. It does not upload.
To dispatch, connect YouTube, review the scheduled time, and separately
acknowledge that YouTube will make the private upload public at that time.

`POST /api/v1/scheduler/{id}/dispatch` requires both `confirm=true` and
`acknowledge_public_publish=true`. The scheduled time must still be at least
five minutes ahead. The adapter uses the official YouTube
[`status.publishAt` contract](https://developers.google.com/youtube/v3/docs/videos#status.publishAt)
and the existing resumable uploader, account permissions, and provider retries.
Unattended dispatch is disabled. TikTok and Instagram provider scheduling are
not supported by this adapter.

Changes after approval require review again. Successful repeated dispatches
replay the recorded result. Errors known to have occurred before video creation
can be explicitly retried with bounded backoff; uncertain outcomes cannot.
A restart turns an interrupted dispatch into an uncertain state. Find the
upload in YouTube Studio and use reconciliation to verify its private schedule
and metadata with the provider before recording completion.

Cancel an uploaded or uncertain provider schedule in YouTube Studio. Deleting
a local entry cannot cancel its public release, so local cancellation and
project deletion are blocked while its provider state is active or uncertain.
After publication or a cancellation in YouTube Studio, use **Refresh provider
status** to verify the connected owner's video state and release the local
project-deletion guard. A missing video or unauthorized lookup keeps the
record unresolved. Confirmed scheduled uploads through the older direct-upload
route now direct you to this review queue; preview requests remain available.
Connected-account end-to-end verification remains required before promoting
this adapter out of development preview.

## Model cache and benchmarks

Model downloads use immutable pinned revisions of supported public Whisper runtime files, with
`SHORTS_MODEL_DOWNLOAD_WORKERS=4` by default (range 1-8), and at most two
model downloads at once. The model manager reports duration, cache bytes,
cache hits, and file-worker settings. A current complete snapshot is required
before Ready is displayed; the check validates completeness and JSON structure,
not a cryptographic signature of the binary weights. Complete existing legacy
snapshots remain usable offline, and transcription loads the exact discovered
snapshot instead of redownloading it through a symbolic model name.
Worker concurrency follows
the [Hugging Face download API](https://huggingface.co/docs/huggingface_hub/en/package_reference/file_download).

Model cards show Preparing, Downloading, cache validation, and Ready through
status messages, along with live elapsed time, file-worker count, and cached
MiB when available. The busy indicator is indeterminate: no transfer percentage
is inferred from the catalog's approximate model size. Cache validation checks
completeness, not binary authenticity. Failures expose private actionable
categories for dependency, permissions, disk-space, and connectivity problems;
retry is a separate explicit click after addressing the problem. Retry does not
delete partially downloaded files. Cache removal is disabled while downloading.
The model state API adds `phase`, `elapsed_seconds`, `error_code`, `retryable`,
and `progress_measured`; clients must not interpret legacy numeric `progress`
as measured transfer progress while `progress_measured` is false.

Run from the project environment:

```powershell
.\venv\Scripts\python.exe scripts\benchmark_v2.py --model tiny --device cpu --repetitions 3 --output release\benchmark-v21-cpu.json
.\venv\Scripts\python.exe scripts\benchmark_v2.py --model tiny --device cuda --repetitions 3 --output release\benchmark-v21-cuda.json
```

The default reads only complete cached model snapshots. `--allow-download`
explicitly permits a missing supported model to be downloaded anonymously.
Reports include individual samples, min/max/mean/median/p95, cache hit state,
and network permission. Repetitions are bounded to 1-10. Current tiny cached
load medians are 0.2880s CPU/int8 and 0.1795s CUDA/FP16; normal synthetic
render medians are 1.3220s and 1.3341s. Device selection affects Whisper loading;
these timings do not claim GPU video encoding or inference accuracy.

To time actual decoding, add `--inference`. By default it generates a two-second
tone; use `--inference-media C:\path\sample.mp4` for the first 30 seconds of
your own local file. Inputs stay local; reports do not include source paths or
transcript text. The worker uses offline mode, English, beam size five, and no
VAD filtering, exhausts the lazy segment iterator inside each timer, and reports
first/warm samples and median real-time factor. Model loading and audio extraction
are excluded from decoder timings. `--timeout` bounds the whole inference worker,
including all repetitions and model loading (5-300 seconds).

CUDA model loading alone does not prove decoding works: cuBLAS/cuDNN libraries
are needed at inference time. With `--device cuda --inference`, optionally pass
`--cuda-library-dir C:\path\cuda\bin` to expose already installed DLLs only to
the child process. No library installation or global PATH change is performed.
Unavailable requested stages now return a nonzero exit code. Synthetic inputs
are runtime checks, not representative speech or transcription-accuracy evidence.

On 2026-10-02, cached tiny-model synthetic-tone decoding passed three samples:
CPU/int8 0.5106s first and 0.3070-0.3153s warm; CUDA/FP16 30.5364s first and
0.1106-0.1646s warm with explicitly supplied existing CUDA libraries. The large
CUDA first-pass cost is retained, not discarded as an outlier. Larger-model,
speech accuracy, and cold-download gates are still open.

### Isolated cold downloads

```powershell
.\venv\Scripts\python.exe scripts\benchmark_downloads.py --model base --allow-download --workers 4 --output release\benchmark-v21-download-base.json
```

Each sample uses a fresh temporary Hub and Xet cache, downloads only the pinned
public runtime artifacts anonymously, and deletes that test cache afterward.
Existing models are not removed, modified, or reused. `--allow-download` is
required; repetitions are bounded to 1-3, workers to 1-8, and the per-sample
child deadline to 10-600 seconds (`--timeout`, default 180). Reports contain no
tokens, source URLs, or local paths. Temporary downloads are intentionally not
installed into the app's normal model cache.

Effective MiB/s divides validated runtime artifact bytes by wall time, including
metadata and cache writes; it is not wire bandwidth. Offline completeness
validation is measured separately. These are local-cache-cold checks, not
provider/CDN-cold checks. A single sample does not establish a worker-count
speedup. Initial 2026-10-02 tiny/4-worker and base/1-worker samples measured
2.3134s (32.2392 MiB/s) and 2.2927s (61.5125 MiB/s), respectively.
Base with four workers measured 2.0411s (69.0951 MiB/s) in a separate single
sample; repeat with representative network conditions before comparing workers.

## Repeatable runtime verification

```powershell
.\venv\Scripts\python.exe scripts\verify_v21.py --output release\v21-source-check.json
.\venv\Scripts\python.exe scripts\verify_v21.py --executable dist\ShortsStudio\ShortsStudio.exe --output release\v21-packaged-check.json
```

The harness generates its own two-second video with on-screen text and a pure
tone, uses isolated temporary job state and a random authentication token, and
removes its test media after shutdown. It checks real speech analysis, evidence
clearing, authenticated access, and clean process exit. If Tesseract is present,
it also requires the text to appear in story search. Use `--require-ocr` to fail
instead of reporting OCR unavailable, and `--tesseract` for an explicit executable.
CI requires OCR on Linux and checks speech in the freshly built Windows bundle.

Both source and fresh Windows portable-runtime checks passed locally on
2026-09-30. OCR was explicitly reported unavailable, not passed.
Cold-download throughput, larger models, representative creator footage,
actual OCR language data, authenticated provider behavior, and installer/remote
release verification remain on the v2.1 release checklist.
